# 来源及限制

## 来源

- Vivado：团队提供的 bx71_uart.xpr、bx71_uart.srcs.zip 与 design_1_wrapper.v，按原目录关系组合；未替换 IP 设置或管脚约束。
- 识别：团队提供 bx71_gesture_source.tar.gz；五个原始文件保留不变。该目录的 README.txt 是开发早期说明，其“尚未实机验证”状态已由后来团队测试反馈更新，以仓库根 README 的验证范围为准。
- 采集：团队上传 bx71_capture(1).c，以标准文件名 bx71_capture.c 收录，内容未改动。
- 运行脚本：团队通过串口读取 `/etc/bx71_gesture_start.sh` 后提供的内容。
- 启动项：团队读取 `/etc/inittab` 第 43 行提供；归档去除了显示行号。
- 文档及 SHA256SUMS 为本次归档新增。没有为原项目擅自指定开源许可证。

## 第三方依赖

使用 OpenCV、OpenCV Zoo 所用的 MediaPipe 手掌检测与手部关键点 ONNX 模型，以及 AMD/Xilinx Vivado IP。第三方代码、工具和模型的权利归相应权利人；本归档不重新授权这些组件。模型权重和 OpenCV 库未随包分发，使用或再分发前应保留相应来源、版本与许可证。模型文件的确切名称见部署说明，不能仅凭同类模型名替换。

## 当前实现的边界

1. V4L2 采集程序请求 640×480，实际协商尺寸以采集日志为准。优先 MJPEG，跳过前四个有效帧，第五帧保存 JPEG；每次调用都重新打开与关闭摄像头。
2. 采集程序也可保存 YUYV 原始数据，但联动脚本只读取 `.jpg`，因此当前完整链路要求摄像头提供 MJPEG。YUYV 回退没有接入识别链路。
3. 识别程序每次启动重新加载模型，运行两阶段 DNN，再按关键点几何规则分类；不是另外训练的四分类网络。角度、遮挡、背景等会影响结果，UNKNOWN 不产生新命令。
4. 连续确认和防重复在 shell 实现；紧急蜂鸣 3 秒期间阻塞新采集。无效结果不会关闭之前的灯。相同有效状态只有在其他状态实际执行后才能再次触发。
5. 原始脚本保留：动作阶段 devmem 失败未做完整恢复；识别进程的退出码未单独检查；异常强制退出可能留下锁目录。首次准备等待有约 90 秒上限，失败不会自动重启。归档不把这些机制描述成完备的故障安全保障。
6. 包内没有 Linux/设备树完整重建配置、OpenCV 交叉构建配方、模型权重、最终 FPGA 加载文件；因此不是全依赖、自包含复现包。已工作的板卡运行结果来自团队反馈，归档环境仅完成静态核对。
